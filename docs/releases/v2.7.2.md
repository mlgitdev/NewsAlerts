# NewsAlerts v2.7.2 Release Notes

**Release Date:** 2026-10-22  
**Release Tag:** `v2.7.2`  
**SemVer Specification:** `2.7.2` (Major: 2, Minor: 7, Patch: 2)  

---

## 🚀 Overview

NewsAlerts `v2.7.2` resolves a configuration testing bug where Telegram bot notifications and Alpaca broker API keys could not be tested directly from the Settings dialog without first saving and reopening the window.

---

### 🎯 Closed Issues

- **Issue [#31](https://github.com/mlgitdev/NewsAlerts/issues/31)**: `fix(settings): test telegram and alpaca credentials without saving first` — Resolved in PR [#32](https://github.com/mlgitdev/NewsAlerts/pull/32).

---

### 🌟 Key Fixes & Improvements

### 1. In-Flight Telegram & Alpaca Connection Testing
- **Immediate Credential Testing**: Updated Settings dialog test handlers to send the in-flight values from the input fields directly to `/api/test_telegram` and `/api/test_alpaca`.
- **Zero Save-and-Reopen Overhead**: Traders can now enter or update their Telegram `bot_token` and `admin_chat_id` (or Alpaca `key_id` and `secret_key`), and immediately click **"✈️ Send Test Message"** or **"▶ Test Alpaca Connection"** to verify connectivity without needing to save and reopen the settings pane.
- **Graceful Fallback**: If the fields are left blank, backend services automatically fall back to saved configuration or credentials in `%APPDATA%\NewsAlerts\keys.toml` (or local `secrets/keys.toml`).

### 2. Backend API & Service Enhancements
- Updated `TelegramService.send_test_message()` to accept optional `bot_token` and `chat_id` overrides.
- Updated `Api.send_telegram_test()` and `Api.test_alpaca()` to accept optional in-flight credentials.
- Updated `/api/test_telegram` and `/api/test_alpaca` routes in `app/server.py` to parse JSON request bodies.
- Expanded automated unit test suite from 26 to 30 tests covering credentials forwarding and route handling.
