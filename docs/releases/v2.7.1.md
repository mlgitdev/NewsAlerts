# NewsAlerts v2.7.1 Release Notes

**Release Date:** 2026-10-21

---

## 🚀 Overview

NewsAlerts `v2.7.1` establishes institutional development lifecycle automation, end-to-end Issue-First traceability, automated CI release generation, and remote wiki synchronization upon merge to `main`.

---

### 🌟 Key Enhancements

### 1. Issue-First Protocol & Lifecycle Skill (`.agents/skills/issue/SKILL.md`)
- **Operational Issue Skill**: Added dedicated AI agent skill for discovering, inspecting, claiming, and creating GitHub issues via GitHub CLI (`gh`).
- **End-to-End Traceability**: Codified mandatory Issue-First lifecycle across `AGENTS.md` and `CONTRIBUTING.md`: every user request, feature, bug fix, or maintenance task must originate from an issue, correlate with dedicated git worktrees, link in PR descriptions (`Resolves #<issue>`), cross-post status comments, and document in release notes.
- **Developer CLI Tasks**: Added `build.ps1 -Task issue-list` and `build.ps1 -Task issue-view` (with cross-platform `make issue-list` and `make issue-view ISSUE=<number>` targets).

### 2. Standardized Issue Templates & Validation Bot
- **Structured Issue Templates (`.github/ISSUE_TEMPLATE/`)**:
  - `bug_report.md`: Standardized reproduction steps, expected behavior, logs, and system environment info.
  - `feature_request.md`: Standardized motivation, user stories, technical considerations, and acceptance criteria.
  - `task.md`: Dedicated template for refactoring, performance tuning, and CI/CD maintenance.
  - `config.yml`: Interactive GitHub chooser with direct links to documentation and wiki.
- **Automated Issue Validator (`.github/workflows/issue-validator.yml`)**: Automatically validates newly opened issues, enforces Conventional Commit title syntax, verifies template sections, applies issue labels (`bug`, `enhancement`, `task`, `needs-triage`), and posts actionable completion feedback.

### 3. Automated Inactivity Reminders & Stale Lifecycle
- **Stale Issues Automation (`.github/workflows/stale-issues.yml`)**:
  - Automatically posts inactivity reminder comments after **7 days** of inactivity (`reminder-sent`).
  - Marks issues as **stale** after **30 days** of inactivity.
  - Closes unresolved stale issues after **37 days** (7-day post-stale grace period).
  - Exempts pinned, security, and in-progress labeled issues.

### 4. Post-Merge CI Release & Wiki Synchronization
- **Automated Release Trigger on `main`**: Updated `.github/workflows/release.yml` with `push: branches: [main]` trigger and intelligent `check-release` gate. Merging a PR to `main` with a bumped `VERSION` automatically initiates multi-OS compilation (Windows x64 executable, macOS arm64 bundle, Linux x64 package), verifies binary signatures and checksums, creates the remote git tag, and publishes the GitHub release.
- **Automated GitHub Wiki Sync**: Added automated wiki synchronization to `.github/workflows/ci.yml` and `release.yml`. Every merge or push to `main` automatically runs `scripts/sync_wiki.py`, keeping all guides in `docs/wiki/` and footer version badges synchronized with `NewsAlerts.wiki.git`.
- **Refined PR Validator (`.github/workflows/pr-validator.yml`)**: Decoupled title and body checks to prevent cascading false-positive errors, expanded description length limit to 120 characters, and added support for `task` commit types.
